# DpadTV 二次开发实施计划

**版本：** V1.0  
**基础项目：** https://github.com/AresCNZJ/DpadTV  
**目标平台：** Fire TV / Android TV  
**设计参考：** 爱壹帆的内容发现、导航、筛选和详情页体验  
**技术路线：** Kotlin 原生客户端 + LibreTV API，按需增加影视元数据服务

## 1. 产品目标

将 DpadTV 从一个以搜索和豆瓣榜单为主的影视客户端，升级为完整的电视端影视浏览应用。

核心体验：

- 打开 App 就能发现值得看的内容，而不必先输入影片名称。
- 通过拼音首字母、完整拼音、中文片名和英文片名快速搜索。
- 通过分类、地区、年份和排序发现影片。
- 在卡片上显示评分、年份、更新状态。
- 保留 DpadTV 现有的换源、续播、直播和播放功能。
- 完整兼容 Fire TV 遥控器操作。

## 2. 页面架构

### 2.1 全新首页

参考爱壹帆的内容组织方式，但采用独立的电视端视觉设计。

```text
首页  电影  电视剧  综艺  动漫  搜索  历史  设置

┌──────────────────────────────────────────┐
│            本周精选 / 大幅海报             │
│      电影名称 · 评分 · 年份 · 简介          │
│        [查看详情]  [加入收藏]             │
└──────────────────────────────────────────┘

继续观看                           查看全部
[海报] [海报] [海报] [海报] [海报]

最近更新                           查看全部
[海报] [海报] [海报] [海报] [海报]

热门推荐                           查看全部
[海报] [海报] [海报] [海报] [海报]

豆瓣高分                           查看全部
[海报] [海报] [海报] [海报] [海报]
```

首页推荐分为四类：

1. **继续观看：** 读取本地播放记录，按照最近播放排序。
2. **最近更新：** 使用各资源站提供的内容更新时间。
3. **热门推荐：** 第一版使用已有的榜单排名信号。
4. **豆瓣高分：** 使用已有的豆瓣推荐数据及可验证的评分。

第一版不做复杂 AI 推荐。优先确保推荐结果合理、数据准确、交互流畅。

### 2.2 首页顶部导航

固定一级导航：

`首页 / 电影 / 电视剧 / 综艺 / 动漫 / 搜索 / 观看历史 / 设置`

保留遥控器方向键移动、OK 确认、返回键恢复上一级焦点。

动画、综艺等分类只有在数据源支持对应类型时才显示有效内容，不把空分类伪装成有内容。

## 3. 搜索系统增强

**优先级：P0**

### 3.1 首页搜索框

在首页导航区增加常驻的搜索入口。选择后进入独立搜索页面。

搜索页采用左右分栏：

```text
┌────────────────┬─────────────────────────┐
│ 搜索：LLDQ      │ 搜索建议                │
│                │                         │
│ A B C D E F    │ 流浪地球                │
│ G H I J K L    │ 流浪地球2               │
│ M N O P Q R    │                         │
│ S T U V W X    │ 热门搜索                │
│ Y Z 0 1 2 3    │ [电影] [剧集] [综艺]    │
│                │                         │
│ 删除  清空 搜索 │                         │
└────────────────┴─────────────────────────┘
```

### 3.2 支持多种搜索方式

| 输入方式 | 示例 |
|---|---|
| 中文完整片名 | 流浪地球 |
| 拼音首字母 | LLDQ |
| 完整拼音 | liulangdiqiu |
| 英文片名 | Interstellar |
| 中文片名部分匹配 | 流浪 |
| 历史搜索 | 遥控器直接选择 |

### 3.3 首字母搜索实现方案

添加拼音索引模块，对已知影片建立搜索索引：

- 标准化中文标题和英文标题。
- 生成拼音全拼与首字母。
- 保存别名、原名及上映年份。
- 搜索时优先匹配精确标题，其次匹配首字母、拼音和模糊标题。
- 搜索建议结果使用本地缓存，减少网络请求。
- 用户确定目标影片后，再向 LibreTV 的现有多源搜索 API 发送真实片名。

**关键限制：** 现有 LibreTV 搜索接口不能保证采集站识别拼音首字母。因此必须先把 `LLDQ` 匹配为《流浪地球》，再用中文片名查询资源。要覆盖未缓存的全部影片，需要额外的影视目录索引。

### 3.4 搜索性能

- 本地输入联想采用防抖。
- 取消过期的远程查询。
- 相同关键字尽量复用缓存。
- 记录用户最近搜索。
- 网络异常时仍显示本地搜索历史与可用建议。

## 4. 分类、筛选和排序

**优先级：P0**

电影、电视剧等分类页顶部统一增加筛选条。

```text
地区：全部 / 中国 / 欧美 / 韩国 / 日本
类型：全部 / 动作 / 喜剧 / 科幻 / 悬疑
年份：全部 / 2026 / 2025 / 2024 / 更早

排序：最近更新 ▼ | 热度最高 | 豆瓣评分最高
```

### 4.1 更新时间排序

默认降序。

字段：`updatedAt`

优先使用资源站提供的影片更新日期；对于连续剧，尽可能使用最新剧集更新时间。

区分“影片上映年份”和“资源更新日期”，不能用上映年份代替更新日期。

### 4.2 热度排序

字段：`popularityScore`

第一版优先采用已获取榜单中的名次作为热度代理指标，并明确标识为榜单热度。

未来如果建立自己的后台，可以加入经用户授权收集的播放、收藏或点击聚合数据，形成站内热度。

### 4.3 豆瓣评分排序

字段：`doubanRating`

- 评分必须转换为数值，降序排序。
- 无评分作品默认排到最后。
- 同名不同年份影片需要分别匹配。
- 展示评分来源，不能把其他平台评分冒充豆瓣评分。
- 外部评分数据的获取、缓存和展示需要遵守提供方的使用规则。

### 4.4 排序范围要求

不能只把当前已加载的 48 条结果排序后宣称是全部影片排行榜。

完整排序需要以下任一种支持：

- 后端直接提供已经排序的数据集。
- 客户端拥有完整且有效的分类目录缓存。
- 额外的目录服务支持排序及分页查询。

## 5. 影视元数据模块

**优先级：P0，排序和推荐的基础依赖**

建立统一影视数据模型，包含：

| 字段 | 用途 |
|---|---|
| `mediaId` | 影片唯一 ID |
| `title` / `aliases` | 标准片名与别名 |
| `pinyinInitials` | 首字母搜索 |
| `fullPinyin` | 全拼搜索 |
| `year` | 上映年份 |
| `category` / `genre` | 分类筛选 |
| `region` | 地区筛选 |
| `updatedAt` | 更新时间排序 |
| `doubanRating` | 豆瓣评分 |
| `popularityScore` | 热度排序 |
| `posterUrl` | 海报 |
| `sourceRefs` | 对应可用片源及影片 ID |

数据处理步骤：

1. 读取已配置的合法影视目录与榜单接口。
2. 标准化标题、年份、分类等字段。
3. 按标题、年份和外部 ID 尽可能准确去重。
4. 建立拼音索引。
5. 补充有权使用的评分及海报元数据。
6. 缓存结果供首页、搜索和分类页重复使用。

要明确区分**影片元数据目录**与**实际可播放资源**。

推荐列表中的作品未必有可播放片源，选择影片时仍需检查已配置的资源接口；搜索不到时显示合理的空状态。

## 6. 技术架构调整

### 6.1 保留现有能力

保留：

- Kotlin 原生 Android TV 技术路线
- Media3 / ExoPlayer
- LibreTV 登录和连接逻辑
- 多源搜索与播放地址解析
- 播放历史、续播、缓存
- 片源管理、直播和换源

第一阶段不迁移到 Jetpack Compose，避免在功能改造过程中引入不必要的全面重写。

### 6.2 拆分 MainActivity

现有主 Activity 集中了搜索、首页、推荐和管理等功能，后续扩展困难。

计划逐步拆分为：

```text
app/
├── ui/
│   ├── home/
│   ├── search/
│   ├── catalog/
│   ├── detail/
│   └── components/
├── data/
│   ├── model/
│   ├── repository/
│   └── cache/
├── search/
│   └── PinyinSearchIndex
├── recommendation/
│   └── RecommendationEngine
├── api/
│   ├── LibreTvApi
│   └── MetadataApi
└── player/
```

这是目标模块结构，不要求一次性重构全部旧代码。

先抽出共用数据模型、搜索、推荐和 UI 组件，保留现有播放器代码的稳定性。

### 6.3 服务端架构

```text
              Fire TV / Android TV
                      │
                新版 DpadTV
                      │
             ┌────────┴────────┐
             │                 │
      LibreTV API         元数据目录
             │                 │
       Vercel 部署        本地缓存优先
             │                 │
        搜索 / 详情       榜单 / 拼音索引
        片源查询          评分 / 排序
        播放地址
```

**优先复用你计划部署在 Vercel 的 LibreTV 服务端。**

第一版先尝试仅客户端本地缓存与现有 API，验证实际可用范围。

如果需要完整目录、跨设备统一推荐、全量更新时间排序，再增加轻量级元数据 API 与持久化数据存储。

Vercel 无状态函数不能当作可靠的持久化本地数据库；需要持久数据时，应使用外部数据库或对象存储。

## 7. 电视 UI 设计规范

目标采用深色背景、突出海报、清晰文字和大面积可见焦点的设计。

设计原则：

- 以 1080p 电视界面作为基础布局。
- 优先支持遥控器，而非触摸屏交互。
- 聚焦卡片有明确描边和轻微放大。
- 横向滚动栏目保持当前选中位置。
- 页面返回时恢复原来的焦点与滚动位置。
- 海报懒加载，避免一次加载全部图片。
- 网络失败显示占位图和重试入口。
- 预留电视安全边距，防止界面被裁切。
- 图片和海报尽量复用缓存。

视觉上参考爱壹帆的导航结构与内容层级，但采用独立的配色、组件、图标和品牌标识，不直接复制商业 App 的专有素材。

## 8. 开发顺序

| 阶段 | 开发内容 | 阶段交付 |
|---|---|---|
| P0 基线 | Fork 仓库、构建 APK、回归测试、整理代码结构 | 可正常运行的独立分支 |
| P1 搜索 | 常驻搜索入口、拼音索引、首字母联想、搜索历史 | 新搜索页 |
| P2 首页 | 顶部导航、推荐横栏、继续观看、最近更新模块 | 新首页 |
| P3 数据 | 元数据标准化、分类索引、更新时间及评分映射 | 可供排序的数据目录 |
| P4 排序 | 最近更新、热度、评分，分类筛选与分页 | 完整筛选页 |
| P5 UI | 统一卡片、焦点、详情页、加载与错误状态 | 统一电视端设计 |
| P6 验收 | Fire TV 真机测试、构建发布和回归修复 | 可安装 APK |

每一阶段单独提交代码并验证，不把全部改动合并成一个无法回退的大版本。

## 9. 验收标准

### 功能验收

- 输入 `LLDQ`，当目录中有《流浪地球》时能正确推荐。
- 搜索页面支持中文、英文和拼音匹配。
- 首页至少展示继续观看、热门、最近更新和高分栏目。
- 三种排序依据明确，结果在同一数据集上保持稳定。
- 对缺少更新时间或评分的作品提供明确处理规则。
- 点击推荐内容后能查找对应片源，没有可用源时不会误导用户。
- 现有播放器、换源、续播、片源管理功能不发生回归。

### 电视兼容性验收

- Fire TV 方向键、OK、返回键导航正确。
- 任何页面不会出现焦点丢失或无法返回。
- 快速连续移动海报时不会明显卡顿或串图。
- 网络超时、片源失效、海报失败不会导致闪退。
- 无须连接鼠标即可完成搜索、选择与播放。

## 10. 开源授权与发布

DpadTV 采用 GPL-3.0。二次分发时，需要保留对应许可证声明、提供符合 GPL 要求的源代码，并遵守第三方依赖的许可要求。

按照项目作者说明，独立发行版本必须更换：

- 应用名称
- 应用图标
- Android 包名

同时注明这是基于 DpadTV 修改的非官方版本。

影片元数据、封面和视频内容也应使用有权访问和展示的来源。

## 11. V1 不开发的功能

为了控制第一版范围，暂时不纳入：

- AI 个性化推荐算法
- 多用户账号系统
- 跨设备观看历史同步
- 原生 Android 手机触控版
- 影片离线下载
- 自建视频存储与转码服务

这些功能可以在电视版主要体验稳定后再评估。

## 12. 第一版完成标准

V1 的核心成果是：

**用户打开 Fire TV 上的 App，就能看到有组织的推荐内容；通过遥控器输入影片拼音首字母快速找到影片；根据更新时间、热度及豆瓣评分筛选排序；最后进入现有 DpadTV 播放器观看。**

在实现这些体验的同时，尽量保持对原版 LibreTV API 的兼容，并控制额外服务器成本。
